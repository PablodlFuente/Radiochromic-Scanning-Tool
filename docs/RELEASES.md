# Releases and packaging

## Release contents

Every published release provides:

- `RadiochromicFilmAnalyzer.exe`, a self-contained Windows application;
- `radiochromic_scanning_tool-<version>-py3-none-any.whl`, for Python environments;
- the source ZIP and TAR archives generated by GitHub.

The executable keeps writable data beside itself. The `calibration_data`, `logs`, `temp`, `rc_config.json` and `recent_files.json` paths are not stored inside the one-file extraction directory.

## Versioning

The authoritative application version is `app/version.py`. `pyproject.toml` uses the same version for the wheel. A release tag must be `v<version>`; the release workflow rejects a mismatching tag.

The application updater queries the latest published GitHub Release. Branch commits, draft releases and unreleased changes are ignored. The executable asset name is `RadiochromicFilmAnalyzer.exe`.

## Local build

From the repository root:

```powershell
python -m pip install -r requirements.txt build pyinstaller
python -m unittest discover -s tests -v
python -m build --wheel
python -m PyInstaller --clean --noconfirm radiochromic_scanning_tool.spec
```

The release artifacts are written to `dist/`. Run the executable from that directory and confirm that the log records both bundled plugins before publishing.

## Publishing

1. Update `app/version.py` and the project version in `pyproject.toml`.
2. Run the complete test and local packaging commands.
3. Commit the release-ready state.
4. Create and push the matching tag, for example `v2.0.0`.
5. The GitHub Actions release workflow reruns the tests, builds the wheel and executable, and attaches them to the GitHub Release.
