# Releases and packaging

## Release contents

Every published release provides:

- `RadiochromicFilmAnalyzer-Setup.exe`, a per-user Windows installer containing `RadiochromicFilmAnalyzer.exe`;
- `radiochromic_scanning_tool-<version>-py3-none-any.whl`, for Python environments;
- the source ZIP and TAR archives generated by GitHub.

The installer defaults to a writable per-user `LocalAppData` location and creates `calibration_data`, `logs`, `temp`, `custom_plugins` and `docs` beside the application.  `rc_config.json` and `recent_files.json` are created on first application use.  The one-file extraction directory never stores persistent data.

An update downloads and runs the latest installer only after the application process exits.  The installer has a stable application ID, so it reuses the existing installation location and replaces application files without deleting calibration data, custom plugins, logs, temporary files, configuration or recent-file records.

## Versioning

The authoritative application version is `app/version.py`. `pyproject.toml` uses the same version for the wheel. A release tag must be `v<version>`; the release workflow rejects a mismatching tag.

The application updater queries the latest published GitHub Release. Branch commits, draft releases and unreleased changes are ignored. The installer asset name is `RadiochromicFilmAnalyzer-Setup.exe`.

## Local build

From the repository root:

```powershell
python -m pip install -r requirements.txt build pyinstaller
python -m unittest discover -s tests -v
python -m build --wheel
python -m PyInstaller --clean --noconfirm radiochromic_scanning_tool.spec
iscc /DAppVersion=2.1.6 installer\RadiochromicFilmAnalyzer.iss
```

The release artifacts are written to `dist/`. Run the installer, verify the Start-menu shortcut and confirm that the installed application's log records both bundled plugins before publishing.

## Publishing

1. Update `app/version.py` and the project version in `pyproject.toml`.
2. Run the complete test and local packaging commands.
3. Commit the release-ready state.
4. Create and push the matching tag, for example `v2.0.0`.
5. The GitHub Actions release workflow reruns the tests, builds the wheel, application executable and installer, and attaches the installer and wheel to the GitHub Release.
